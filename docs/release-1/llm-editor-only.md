# LLM в Lexy: режим editor-only

## Назначение

В R1 добавлен ограниченный LLM-контур для понятного объяснения уже рассчитанного `ReportViewModel`. LLM не участвует в rules engine, не выбирает риск, уровень, статью, санкцию, рекомендацию или необходимость эскалации.

## Включение

Режим включается только явно и только на техническом Pilot-контуре:

```text
LEXY_R1_LLM_MODE=editor_only
LEXY_R1_LLM_PROVIDER=builtin
LEXY_R1_LLM_MODEL=gpt-5-mini
```

При отсутствии этих флагов процедура возвращает ошибку, а интерфейс сохраняет канонический отчёт без LLM. Production client runtime по-прежнему закрыт release gate.

## Приоритет источников

1. Переданный immutable snapshot и правила проекта.
2. Записи `legal_basis_catalog_v1`, уже связанные с рисками.
3. Российское законодательство и практика — только как основание пометить необходимость проверки человеком; новые нормы нельзя добавлять в результат.
4. Свободный интернет в editor-only вызове запрещён. Неподтверждённый источник должен быть отмечен как требующий human source review.

## Проверки результата

Перед возвратом editorial draft выполняются JSON Schema validation, проверка длины и типов полей, проверка уникальности и принадлежности risk ID, проверка принадлежности legal basis ID разрешённому каталогу и контроль того, что детерминированный результат не изменён.

В интерфейсе явно указано, что это редактура snapshot и что вывод требует проверки человеком. При ошибке провайдера, schema или source guard используется исходный канонический отчёт.

## Содержание запроса

LLM получает только безопасную проекцию отчёта: title, summary, risks, legalBases, roadmap, recommendation, escalation и limitations. Исходные ответы анкеты, session identifiers, payment identifiers, storage keys и внутренние provenance-поля в prompt не передаются.
